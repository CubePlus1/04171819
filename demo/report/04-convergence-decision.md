# 04 · 强制收敛决策

## 定位

| 位置 | 方案 |
|---|---|
| **主方案** | 主 demo（`dundao-demo` / `feat/dundao-demo`） |
| **备胎方案** | 主 demo 的**单面板模式**（URL `?panel=product-only` · 10 分钟加） |
| **淘汰方案** | Echo（`dundao-echo` / `feat/dundao-echo`） |

## 4 个关键问题

### 1. 为什么主方案最符合赛道三？

赛道三核心：**"信息流中的下一条内容单元"**。

**主 demo 左面板里的履约卡片字面就是这个东西：**
- 它在信息流里 · 不在弹窗 / 不在新页面
- 它是卡片 · 不是对话 / 不是列表 / 不是 chatbot
- 被刷到的那一秒就**物理成立** · 不需要语言解释

Echo 不符合：
- 形态是"一页聊天线程" · 结构性违反"信息流卡片"
- 访问路径是"主动打开网页" · 违反"被动刷到"

**结论**：主方案在赛道三核心锚点上是**物理成立**，Echo 是**语言说服**。差别在于是否需要评委相信你的叙述。

### 2. 为什么主方案最适合 40 小时黑客松？

**沉没成本 + 成熟度 · 两个维度**：

**沉没成本**：
- 主 demo 已经投入 ~25 小时（初版 + ambient 改造 + MindCanvas + 10 轮 codex + 12 主题）
- Echo 投入 ~8 小时（初版 + ambient + MindCanvas）
- 主 demo 的沉没成本更高 · 已经接近完成

**成熟度**：
- 主 demo：10 轮 codex review + 全绿测试 + 91/100 final go
- Echo：10 轮 codex review + 全绿测试 + 91/100 final go

两者工程层面都成熟。但**剩余时间的边际回报**不同：
- 主 demo：剩余时间只需 pitch polish · 每小时都在讲故事
- Echo：要追到能上展台 · 还需改变形态本身 · 等于重新做

**结论**：剩余 40 小时只有一个方案能容纳 · 必须选主 demo。

### 3. 为什么主方案最适合大学生展览？

大学生展览的**物理场景约束**：

**评委停留时间**：
- 路人：3-5 秒瞄一眼
- 评委：60-90 秒
- 极少：3 分钟深入

**主 demo 在每个时间尺度都有价值**：
- 3 秒：看到 12 主题切换 + 双面板 · 视觉钩子
- 60-90 秒：看完 1-2 个剧本的履约过程
- 3 分钟：3 剧本 + AI 5 相位 + 技术亮点

**Echo 在每个时间尺度都弱**：
- 3 秒：看到一页纸面对话 · 容易被误认为博客
- 60-90 秒：刚好一轮对话结束 · 来不及体验 3 剧本
- 3 分钟：能看到 3 轮 · 但形态未变

**展台上的情感钩子**：
- 爷爷剧本在主 demo 的卡片里呈现 · 视觉冲击强
- 同一剧本在 Echo 里是几个气泡 + 一张明信片 · 情感浓 · 但视觉弱

**结论**：展台优势完全倒向主 demo。

### 4. 为什么主方案最不依赖复杂 API？

**数据层**：
- SQLite 单文件 · 零外部依赖
- 所有数据 seed 自 `fixtures.json` 本地
- 不调用抖音 API / 不调用 LLM API / 不调用任何外部服务

**AI 层**：
- 意图分类是**规则引擎**（`intent.js` 的 `INTENT_RULES`）
- topic 匹配是**SQL JOIN**（`ambient.js`）
- action_type → script 是**字典映射**（`ACTION_TO_SCRIPT`）
- 完全不跑 LLM · 展台时延稳定

**网络层**：
- 前后端在同一机器 · localhost 通信
- WebSocket 走本机回环
- 展台无需外网 · 插 WiFi 只为 web fonts（Google Fonts · 挂了也只影响字体，有 fallback）

**风险抵御**：
- 断网：核心功能不受影响
- 抖音改版：不影响（没接）
- OpenAI API down：不影响（没接）
- 数据库挂：SQLite 文件可以删了重 seed · 10 秒恢复

**结论**：主 demo 是 offline-first · 展台场景下接近零外部依赖。

## 为什么不选其它组合

### 不选"Echo + 主 demo 共存"
两个都做到展台级别需要**再 20 小时** · 我们没有。
多 demo 分散讲解时间 · 评委听完反而模糊。
选最强的一个专注打磨 · 是展台常见最佳实践。

### 不选"只做 Echo"
Echo 形态违反赛道三 · 上展台会直接扣分。
即使 Echo 情感浓度高 · 也抵不过结构性不符的扣分。

### 不选"重写一个第 3 方案"
40 小时时间不允许从头再做。
已有两个 demo 选其一 · 哪怕主 demo 只是"相对最优"。

## 备胎方案说明 · 单面板模式

**为什么需要备胎**：
主 demo 最大质疑是"双面板是 demo 还是产品？"。
万一评委特别介意 · 需要一键演示**只有左面板的产品形态**。

**备胎实现**：
URL query 参数 `?panel=product-only`：
- 前端 App.jsx 读 URL · 只渲染 `ProductPanel`
- 宽度占满 · 视觉冲击回到"单屏产品"

**工程成本**：10 分钟（加 URL 参数判断 · 改条件渲染）

**展台用法**：
默认双面板。评委质疑时当场开一个新标签页 · 加参数 · 演示真实产品形态。

**是否现在做**：
**不要现在做**。醒来后的行动清单里没有它。只在"fallback 话术如果不够说服评委"时才动手。先准备话术。

## 淘汰方案说明 · Echo

**为什么淘汰不是"删除"**：
- 代码仓库保留
- commits 保留
- README 加标签"姊妹探索 · 未采用"
- 可作为选型过程证据（面试时讲"测试过两种形态最后选了 A"）

**什么情况会重启 Echo**：
- 赛道变了（从"信息流下一条"变成"AI 陪伴"）· 几乎不可能
- 有 10+ 小时富余时间 · 现在没有
- 主 demo 遇到不可修复问题 · 极端情况

**现在的动作**：
1. Echo README 加标签
2. 展台不展示
3. 不再投入工程时间
