# 06 · 可行性 + 资产复用 + 工程预算 + 风险

## 可行性结论

40h 纯软件 MVP 可落地，采用 **γ 双模切换** 策略。

> **观众模式（默认）稳定展示胶囊 wow，评委模式（按钮触发）展示真实 agent 链路。**

---

## 双模策略详解

### 观众模式（默认、95% 时间）

**目标**：稳定、炸、快。

- 预计算矩阵：**6 目的地 × 3 persona = 18 个胶囊**
- 变形切换 = 矩阵查表 + UI 淡入
- TTS 全部预合成（18 条音轨预生成）
- 动态路线图预渲染 Lottie / MP4
- 不依赖网络、不依赖 LLM、不依赖任何实时服务
- 稳定性接近 **100%**

### 评委模式（按钮切换、5% 时间）

**目标**：真，有技术深度。

- 1 条真 RAG 链路：用户输入 / 场景按钮 → 情境识别 → RAG 检索 → LLM 生成胶囊 → 渲染
- 情境识别：规则 + 时间 + 手动 persona
- RAG 源：本地视频字幕库（30-50 条预置样本）
- LLM 生成：火山方舟 Responses API + **Structured Outputs(beta)** 锁 schema
- Agent Trace 层展开：rag_queries / retrieved_videos / selected_reason 实时渲染
- 延迟容忍：30-45s（评委可以等）

### 切换机制

- 按钮切换（显式）
- 不在切换期间运行，切换 = 重建整个 UI 状态
- 切回观众模式有 1s 过渡动画

## 工程预算分配（40h）

| 项目 | 占比 | 绝对时间 | 内容 |
|---|---|---|---|
| 前端 | **40%** | 16h | 胶囊 materialize 动画、情境粒子背景、TTS 播报同步、变形切换、评委侧屏 |
| Agent | **25%** | 10h | 1 条真 RAG 链（复用 nightowl ETL）+ Structured Outputs 胶囊生成 + Agent Trace 渲染 |
| 素材 | **20%** | 8h | 6 目的地 × 3 persona 矩阵 + 晚饭 bonus 素材 + TTS 预合成 |
| 联调 & 彩排 | **15%** | 6h | 双模切换、稳定性、断网兜底、20+ 次走彩排 |

### 时间分配原则

- **素材压榨前置**：素材 authoring 花的是"人肉时间"，要尽早启动（H+0 开始）
- **双模切换殿后**：最后 6h 的联调不是写代码，是把观众模式和评委模式"粘"在一起
- **前端炸点优先**：40% 前端时间里，60% 花在 3 个核心 wow 瞬间（materialize / 变形 / trace 揭幕）

## 资产复用（本地四仓）

### nightowl

**角色**：ETL + RAG 管线

- 已有：轻量 ETL + pgvector 检索骨架
- 本方案用：**抓视频字幕 → 结构化要点 → 存向量**
- 新增工作：字幕源接入（手工样本）、chunk 策略调整
- 复用度：★★★★☆

### Eoove-demo

**角色**：SituationVec 承载 + advisor 壳

- 已有：PersonVec / 问卷 / advisor scenario 骨架
- 本方案用：**PersonVec 架构改造成 SituationVec**、advisor 壳渲染胶囊框架
- 新增工作：situation_vec 字段设计、time 维度新增
- 复用度：★★★★☆

### taidy

**角色**：证据引用面板

- 已有：references 证据结构、NL-to-SQL 图表
- 本方案用：**evidence_chips 的 UI 组件**、Agent Trace 的表格
- 复用度：★★★☆☆

### allin

**角色**：前端壳 + 展示

- 已有：Vue3 + Element Plus + ECharts + 雷达图
- 本方案用：**主展示容器、变形切换的 UI 框架**
- 复用度：★★★★★

## 风险矩阵

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 双模切换 bug | 中 | 高 | 默认观众模式跑预计算，评委模式独立按钮 + 独立路径，避免状态共享 |
| LLM 抖动（评委模式） | 中 | 中 | Structured Outputs 锁 schema + 超时 10s 兜底预计算胶囊 |
| TTS 延迟卡顿 | 低 | 中 | 18 条音轨全部预合成，本地播放 |
| 胶囊变形动画卡顿 | 中 | 中 | 6×3 矩阵预渲染 Lottie / MP4，切换 = 加载 + 淡入 |
| 素材 authoring 超时 | **高** | **高** | 矩阵从 6×3 降到 4×2（8 胶囊）或 3×2（6 胶囊）止损；博主原话从 5 条 / 胶囊降到 3 条 |
| 评委追问"真 agent 在哪" | 中 | 中 | 评委模式 1 条真链 + Agent Trace 可视化 |
| 展台触发机制翻车 | 中 | 低 | 手动 + 自动双入口，手动永远可用 |
| 观众模式过于"demo 感" | 中 | 中 | 加入真实时间 / 天气参数，让"此刻"可信；TTS 播报时间要用"当前" |
| 网络断电 | 低 | 高 | 所有资源本地化，全离线可跑 |

## Kill Criteria（止损点）

按时间节点砍功能：

| 时间节点 | 检查项 | 如果未达成 |
|---|---|---|
| **H+8** | 胶囊 materialize 动画骨架跑通 | 退回静态卡渲染 |
| **H+16** | 至少 2 个目的地（4 胶囊）完整素材就位 | 矩阵从 6×3 降到 4×2 |
| **H+24** | 观众模式 90s 脚本走完不翻车 | 继续彩排，砍评委模式 Agent Trace |
| **H+30** | 双模切换稳定 | 评委模式降级为预录 trace 展示 |
| **H+36** | 整体彩排 10 次 | 砍 Bonus 垂类，只保主 demo |

## 不做什么（YAGNI）

以下内容**明确不做**：

- ❌ 接真实抖音 feed / 视频数据接口
- ❌ 真实个人数据建模（无法在展台兑现）
- ❌ 后端用户系统 / 登录 / 会话
- ❌ 胶囊数据持久化
- ❌ 多用户并发
- ❌ 移动端 App（只做 Web）
- ❌ 真实人体传感器触发（手动 + 时间触发即可）
- ❌ 胶囊导出 / 分享
- ❌ 用户反馈的真实 ML 训练（反馈只更新前端 situation_vec）
