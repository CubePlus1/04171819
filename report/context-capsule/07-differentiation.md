## 与赛道三主流方向的对比

调研报告（`../../py/output/bytecamp-100/reports/master_report.md` 和 `../../langchain/output/20260415-142925/report.md`）里赛道三共有 9 个候选方向，全部集中在"同题多解分叉"家族。

| 方向 | wow 来源 | 数据形式 | 体验角度 | demo_wow |
|---|---|---|---|---|
| `brainstorming-02` 数字分身信息流 | 三列同屏分叉 | 3 张独立卡（并列） | 对比 wow | 9.5 |
| `brainstorming-10` 数字个体实验室 | 人格三分身同题三解 | 3 个 persona 对象 | 深度体验 | 9.2 |
| `bytecamp-05` 今晚吃什么卡片流 | 三列 feed | 传统推荐卡 | 生活决策 | 9.0 |
| `brainstorming-07` 话题同温层 | 双人并排对照 | 兴趣雷达 | 社会议题 | 8.0 |
| `brainstorming-06` 财经秒问 | 同卡变图 | 卡片 + 图表 | 决策验真 | 8.5 |
| `bytecamp-12` 内容分身问数台 | 预置分身回答 | 聊天卡 | 问答 | 7.0 |
| `bytecamp-04` 内容消费人格镜像 | 刷到说明书 | 标签雷达 | 解释型 | 8.0 |
| `bytecamp-06` 空档去不去 | A/B 对决卡 | 事件卡 | 校园决策 | 8.0 |
| `brainstorming-11` 情绪电台 | 状态卡 | 内容卡 | 陪伴 | 8.0 |
| **本方案·情境预言胶囊** | **时间预言 + 单胶囊变形 + 新数据形式本身** | **全新 7 层结构对象** | **新媒介级 wow** | **目标 9.5+** |

### 核心差异

本方案是赛道三 9 个候选方向里**唯一一个不走"多解分叉"路线**的方案。

- **9 个主流方向**赌的都是"视觉对比的瞬时冲击"（三列 / 双人 / A/B）
- **本方案**赌的是"这是一种从未见过的信息单元"（单胶囊 + 变形 + 新数据对象）

前者赌的是 **perception**（感知层），后者赌的是 **category**（范畴层）。

### 两种 wow 的风险对比

| 维度 | 多解分叉类 | 情境预言胶囊 |
|---|---|---|
| wow 获得速度 | 快（第一眼） | 中（需要 5-10s 理解） |
| 记忆点强度 | 中（"三个人刷到不同"） | 高（"这是一种新东西"） |
| 容易被复现 | 容易（动画换个颜色就行） | 难（要重做 schema） |
| 评委分类 | "又一个人格类产品" | **独立品类** |
| 风险 | 方案撞车 | 理解不及 |

### 本方案的押注

我们押：**在 9 个"三列分叉"中间，一个"单胶囊新媒介"会形成独立品类记忆点，评委第一次看到会说 "oh, this is different"**。

## 与 PersonVec / 数字建模人长期目标的关系

用户长期目标是"数字建模人"（PersonVec / Eoove）。

本方案**不直接做 PersonVec**，但**为 PersonVec 提供了一种容器**：

| PersonVec 视角 | 胶囊对应 |
|---|---|
| PersonVec 是"人的向量" | **SituationVec 是"情境的向量"——PersonVec 的时间 / 情境切片** |
| PersonVec 需要可解释训练数据 | **胶囊反馈层（Layer ⑥）产生带语义的反馈 → 可解释训练信号** |
| PersonVec 推理过程需要可观察 | **Agent Trace 层（Layer ⑦）提供可观察快照** |
| PersonVec 需要容器承载输出 | **胶囊 = PersonVec 的 presentation layer** |

**即使 hackathon 结束，胶囊 schema 本身可以作为数字建模人项目的数据标准延续**。

### 路径对比

| 路径 | 先做什么 | 延续性 |
|---|---|---|
| 直接做 PersonVec | 问卷 / 画像 / fusion | 可行但展台 wow 弱 |
| **本方案 · 做胶囊** | 胶囊 schema + 展台 demo | 胶囊是 PersonVec 的容器，反向推动 PersonVec 定义 |

本方案是"**先做容器，再做内容物**"的路径。
容器定义了 PersonVec 需要输出什么、需要接什么反馈、需要 trace 什么。这反而让 PersonVec 的设计更聚焦。

## 与抖音生态的关系

### 对齐官方题面

赛道三题面明确说"**不再只做视频**"。这是官方愿意接受"非视频形态"创新的明显信号。

胶囊是对这个信号的**最直接回应**：
- 不是视频
- 不是短视频增强
- 不是视频的集合
- 是一种**平行于视频**的新内容单元

### 如果未来真的进入抖音生态

胶囊可以：
- 作为 feed 里的**异形卡类型**（当前异形卡权限是行业专供，未来可能开放）
- 作为**精选内容**的独立 tab
- 作为**搜索结果**的聚合形态
- 作为**小程序 / 小游戏**的 AI 原生容器

但这些都**超出本 hackathon 范围**。本 hackathon 只证明"这种数据形式立得住、体验做得出、技术跑得通"。

## 胶囊 schema 的开放可能

如果胶囊作为一种新数据形式能被业界接受，可能演化出：

- **Capsule as a format**：像 JSON / Markdown 一样的开放标准
- **Capsule Editor**：给创作者的胶囊制作工具
- **Capsule SDK**：给第三方集成的 SDK
- **Capsule Discovery Feed**：一个独立的胶囊 feed 产品

以上是假想，不在 hackathon 范围内。

## 附录 · 关键术语

- **Context Capsule（情境预言胶囊）**：本方案提出的新数据单元
- **SituationVec**：情境向量，区别于 PersonVec，是"情境"而非"个人"的嵌入
- **Materialize**：胶囊从"预言"状态变为"呈现"状态的过程
- **Fork（变形）**：同一胶囊换参数重渲染，区别于"生成新胶囊"
- **Agent Trace**：agent 决策过程的可审计记录层
- **γ 双模切换**：观众模式（预计算）+ 评委模式（真 agent）的混合策略
- **L3 情境懂**：把"懂你"的颗粒度从个体换成情境（详见 `03-concept.md`）
