# 阶段 1 · 赛道三题面深读 + 参考方案解读

## 官方题面（原文）

### 赛道三｜AI 体验：刷到懂你的瞬间

> 在抖音，用户每天都会刷过无数条内容，但真正让人停下来的，往往是那一刻——刚好被懂、刚好被满足。
>
> 这一次，我们不再只做视频。我们希望你去创造一种新的信息流内容单元。它不只是被观看，而是在被刷到的那一刻，把你想要的信息、情绪与选择，都刚好准备好。
>
> 它可以是在你纠结今晚吃什么时，刷到一桌已经帮你搭好的美食；也可以是在你准备出门旅行时，刚好出现的一份行程安排；也可能是在一场比赛开始前，把你最关心的阵容和看点提前呈现出来。
>
> 用户不需要跳转，也不需要理解复杂逻辑，而是在刷的过程中，遇到那些"刚好懂你"的瞬间。

---

## 关键词拆解

### 强约束关键词

| 关键词 | 含义 | 约束 |
|---|---|---|
| "**新**的信息流内容单元" | 定义新媒介 | 不能只做旧媒介的增强 |
| "创造一种" | 强调"原创定义" | 要发明，不要拼装 |
| "不只是被**观看**" | 不是被动消费 | 必须有主动交互 |
| "**刚好**准备好" | 精准，not 多样 | 不是多解分叉 |
| "不需要**跳转**" | feed 内闭环 | 单单元完成 |
| "不需要理解**复杂逻辑**" | 直觉易懂 | UX 门槛低 |

### 核心词："**刚好**"

中文"刚好懂你"翻译：
- ❌ **not** "understand you diversely"
- ✅ "just right"

**关键 insight**：官方期待的 wow 来自 **精准感**，而不是 **多样性**。

这对"三列多解分叉"类方向（`brainstorming-02` 数字分身信息流等）是一个**隐性否定**。本方案尊重这个"刚好"，走**单胶囊 + 变形**路径，而不是多胶囊并列。

---

## 官方三个示例

题面给出三个具体场景：

| 场景 | 对应决策类型 | 示例表达 |
|---|---|---|
| 今晚吃什么 | 生活决策 | "一桌已经帮你搭好的美食" |
| 出门旅行 | 计划决策 | "一份刚好的行程安排" |
| 比赛开始前 | 消费决策 | "阵容和看点提前呈现" |

### 共同特征

- 都是**决策型场景**，不是信息消费型
- 都涉及**即将到来的时刻**（不是此刻在做什么，是马上要做什么）
- 都强调**聚合**（一桌 / 一份 / 一页）
- 都要求**提前**（先用户一步准备好）

**推论**：官方期待的是 **"预言 + 聚合 + 决策"** 这三位一体，而不是"推荐 + 浏览"。

## 参考方案解读

官方提供了内部参考方案截图（`../../dimage.png`）。

### 形态描述

一张 AI 生成的"莫干山清明越野跑攻略"聚合卡：

```
标题：莫干山清明越野跑攻略 [AI 生成]
结构化字段：目的地 / 天数 / 气温预估 / 路线风景
路线图：Day 1 - Day 2 动态展示
博主原话 chips：
  - "去越野跑吧！钻林子当猴子其乐无穷！" + 视频缩略图
  - "莫干山山顶喝咖啡超 nice！" + 视频缩略图
决策按钮：不感兴趣 / 查看详情
Feed 上下文：↑ 上滑继续看视频
```

### 设计语言（官方愿意接受的）

1. **单卡聚合**（不是多卡并列）
2. **AI 生成标识**（透明 + 合规）
3. **结构化字段**（目的地 / 天数 / 气温）
4. **博主原话**（从视频提取，保留原语气）
5. **视频缩略图证据**
6. **feed 内嵌**（上下能继续刷）
7. **两个决策按钮**

### 明显的不足

这张卡相对本方案来说还是一个 v0：

- ❌ **被动**：等用户刷到，系统不主动预言
- ❌ **静态**：不会随情境变形
- ❌ **单模态**：只有图文，没有语音 / 动态
- ❌ **单人格**：不区分寝室三人 / 情侣 / 独自
- ❌ **黑盒**：不暴露"为什么推给我"
- ❌ **"清明"已过时**：当前 4-17，清明已过，时间感断裂

### 本方案相对参考方案的升级

| 维度 | 参考方案 v0 | 本方案 v1 |
|---|---|---|
| 触发 | 被动（等刷到） | **主动预言** |
| 时间 | 静态（内容时间） | **双时间（now + predicted_moment）** |
| 模态 | 图文 | **图文 + 语音 + 动态 + 证据 chips** |
| 人格 | 单 | **多 persona 变形** |
| 可审计 | 无 | **Agent Trace 层** |
| 反馈 | 两按钮 | **语义化反馈锚点** |
| 变形 | 不变形 | **参数化变形（by_location / by_group / by_budget）** |

**本方案 = 参考方案形态 + 新数据形式的底层创新**。

## 阅读题面后的 3 个设计方向候选

基于题面深读，浮现三个候选：

| 候选 | 核心思路 | 风险 |
|---|---|---|
| A. 按参考图走 | 单卡聚合，feed 内嵌 | 太像官方示意图，缺原创 |
| B. 三列分叉 | `brainstorming-02` 路线 | 违反"刚好"关键词 |
| C. 重新定义 | 把参考图当 v0，做 v1 | 风险在"评委不懂这是什么" |

**下一步**：Q1 推演 wow 机制选哪个候选（详见 `03-q1-wow-mechanism.md`）。
