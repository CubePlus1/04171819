# Q5 · 40h 工程基调

## 问题

> 下一个关键分叉——"主动触发 + 自主 RAG+ETL"这一条要做到多真？这件事直接决定 40h 的重心在哪。
>
> 40h 工程基调选哪套？

## 候选

| 方案 | 前端 | agent | 素材 | 联调 | wow 优先 |
|---|---|---|---|---|---|
| α · 沉浸剧场流 | 60% | 10% | 15% | 15% | 观众 |
| β · 真 agent 实跑 | 25% | 45% | 20% | 10% | 评委 |
| **γ · 双模切换流** | **40%** | **25%** | **20%** | **15%** | **双** |

### 我的推荐：**γ**

推荐理由：
1. 对齐"一套给评委、一套给观众"明确诉求
2. 观众模式 100% 稳（预计算，不受 LLM 抖动）
3. 评委追问时有真东西（1 条真链足够）
4. 素材矩阵 6×3=18 支持变形不露馅
5. α 冒险（被戳穿），β 反体验权重

## 用户选择：**γ**

> "好的没问题。"

---

## γ 方案详解

### 观众模式（默认 · 跑 95% 的时间）

- 预计算矩阵：6 目的地 × 3 persona = 18 胶囊
- 变形 = 矩阵查表 + UI 淡入
- TTS 全部预合成
- 不依赖网络 / LLM
- 稳定性近 100%

### 评委模式（按钮切换 · 跑 5% 的时间）

- 1 条真 RAG → LLM 链路
- 情境识别：规则 + 时间 + 手动 persona
- RAG 源：本地视频字幕库（30-50 条）
- LLM 生成：火山方舟 Structured Outputs
- Agent Trace 层实时展开

## γ 方案对齐性检查

### vs 用户明确权重

| 用户权重 | γ 如何对齐 |
|---|---|
| 体验最重要 | 40% 前端优先 |
| 展示最重要 | 前端 + 素材 = 60% |
| 游园会唯一评审 | 双模切换服务展台 |
| 主动触发 + 自主 RAG + ETL | 评委模式 1 条真链满足技术深度 |
| 反馈增强 | Layer ⑥ 反馈锚点（前端模拟） |

全部对齐。

### vs 风险

| 风险 | α | β | γ |
|---|---|---|---|
| 评委追问技术被戳穿 | 🔴 高 | 🟢 低 | 🟡 中 |
| 观众 wow 不足 | 🟢 低 | 🔴 高 | 🟡 中 |
| LLM 抖动导致翻车 | 🟢 低 | 🔴 高 | 🟡 中 |
| 工程翻车 | 🟢 低 | 🔴 高 | 🟡 中 |

γ 在所有维度都是"中"，没有致命短板。

### vs 止损

γ 允许在工程超时时砍功能：

- 评委模式翻车 → 降级为"预录 Agent Trace 展示"（仍有技术感）
- 观众模式翻车 → α 兜底（把所有交互都预计算成动画）
- 素材超时 → 矩阵从 6×3 降到 4×2

## 双模切换的技术简述

（实施阶段再详细 freeze）

```
[主入口 App]
    │
    ├─ [观众模式 UI]
    │     └─ 读取：预计算胶囊矩阵 JSON
    │     └─ 渲染：胶囊 component + 预合成 TTS 音轨
    │     └─ 交互：变形 = 切换矩阵索引
    │
    └─ [评委模式 UI]（按钮触发）
          └─ 读取：同 UI 组件
          └─ 数据源切换：调 agent API
          └─ 真实 RAG → LLM → Structured Output → 胶囊 object
          └─ 并行渲染：Agent Trace 面板
```

**关键设计**：两种模式**共享 UI 层**，只切换**数据源层**。
这样前端只开发一次，agent 工作只专注后端链路。
