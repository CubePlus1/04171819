# Q3 · 重新定义"懂你" + 新数据形式方向

## 问题

> 非常有意思的约束——"观众不能感受到被懂"这件事，其实是 AI 展台的根本困境。你的回应很锋利：既然观众不能体验被懂，就把"懂"这件事外化成一种可旁观的新数据形式本身。
>
> 我把"新数据形式"这个点翻译回技术层：不是 UI，不是内容，是一种底层的**多模态数据对象**——像 JSON 是数据、embedding 是数据一样，这是一种新的"懂"的数据对象。参考图里的越野跑卡其实就是 v0 雏形，但还是静态的、被动的、单模态的。
>
> "重新定义懂你" + "新数据形式"，你倾向哪个方向？

## 候选

| 选项 | 新定义 | 新数据形式 | 观众 wow |
|---|---|---|---|
| A | 懂"情境" | 情境胶囊（Situation Capsule） | 识别"清明+微雨+大学生"生成适配单元 |
| B | 懂"预言" | 时空决策胶囊（Temporal Decision Unit） | 提前材料化"晚 7 点吃饭"决策 |
| C | 懂"过程" | Agent 思考流（Thinking Stream Unit） | agent 实时思考即内容 |
| D | 懂"群像" | 动态人格流（Persona Flow Unit） | "大学生此刻平均人格"流动 |
| E | 其他 / 混合 | — | — |

### 我的推荐

**A + B 的组合，以 A 为骨**：

- A 解决"观众能共享情境"：观众自己此刻也在这个情境里
- B 提供戏剧张力：预言比响应更 demo 友好
- 合并后的数据形式 = **"情境预言胶囊"**

## 用户选择：**A+B 主体，C 给评委看 bonus（可砍）**

> "AB 先做，再 C 给评委看，然后的话 C 没时间可以不做，我们要重**展示**，
> 游园会是唯一的评审方式，不需要 PPT，不需要视频，**体验最重要，展示最重要**。"

---

## 四个选项的评估

### A · 懂"情境" × 情境胶囊

| 维度 | 评估 |
|---|---|
| 能解决"观众不能被懂"困境 | ✅ 观众和路过者共享同一"此刻" |
| 展台可落地 | ✅ 情境变量（时间 / 天气 / 节气 / 群体）本地可伪造 |
| 与长期目标对齐 | ✅ SituationVec 是 PersonVec 的时间切片 |
| 工程难度 | 中 |

### B · 懂"预言" × 时空决策胶囊

| 维度 | 评估 |
|---|---|
| 戏剧张力 | ✅ 最强（系统先知 + 准备好） |
| 对齐题面"刚好准备好" | ✅ 预言 = 提前准备 |
| 展台 demo 化容易 | ✅ 时间线上的"未来决策单元" |
| 风险 | 🟡 需双时间字段、预言逻辑 |

### C · 懂"过程" × Agent 思考流

| 维度 | 评估 |
|---|---|
| 技术深度 | ✅ 最深 |
| 观众娱乐性 | 🔴 偏弱（容易变技术秀） |
| 评委喜欢度 | ✅ 高（看到真 agent） |
| 决策 | 用户说"给评委看、没时间可以不做" → 降到 **Bonus** 层（评委模式） |

### D · 懂"群像" × 动态人格流

| 维度 | 评估 |
|---|---|
| 概念有力 | ✅ 但抽象度高 |
| 展台可解释性 | 🔴 观众需要被教"什么是群像人格" |
| 工程复杂度 | 🟠 高（人格向量实时流动） |
| 决策 | **排除**（抽象度过高） |

---

## 重要约束（用户新增）

| 约束 | 含义 |
|---|---|
| 游园会是唯一评审方式 | 没有外部 pitch |
| 不需要 PPT | 所有表达在展台完成 |
| 不需要视频 | 即时体验 |
| **体验最重要、展示最重要** | 40h 所有工程服务展台那一刻 |

**推论**：工程重心 = 展台 60-90s 脚本。所有技术决策围绕"这个脚本是否更 wow"判断。

---

## 命名定案

A + B 融合后的数据形式命名为：

> **情境预言胶囊（Context Capsule）**

组成解释：
- **情境**（Context）= 来自 A，解决"观众共享此刻"
- **预言**（Prophecy / Temporal）= 来自 B，解决"戏剧张力"
- **胶囊**（Capsule）= 暗示"聚合 + 密封 + 可投递 + 可开启"

英文名选用 **Context Capsule**（不用 Temporal 因为太技术化）。
"Prophecy"已内含在 `predicted_moment` 字段，不必在名字里重复。
