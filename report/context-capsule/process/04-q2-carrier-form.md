# Q2 · 载体形态 + 双受众约束

## 问题

> 为了能在 40h 展台上把"新媒介"讲清楚，先定载体形态，因为"主要做的是展示"——观众第一眼看到的是什么决定了全部。

## 候选

| 选项 | 描述 | wow 来源 |
|---|---|---|
| A | 沉浸式 Feed 增强 | 单元 + feed 沉浸 |
| B | AI 决策流 HUD 台（脱离 feed） | 指挥台 wow |
| C | 剧场化双屏（手机 + 大屏） | 后台被打开 |
| D | 多轨联播台（像电视新闻台） | 多形态并列 |
| E | 其他 | — |

## 用户选择：**A+C 组合**

> "A+C，我们需要面向不同对象，一套给评委看内部技术，一套给观众看，wow，
> 但是观众其实不能感受到，我们需要**重新定义懂你**，同时**创新一种数据形式**。"

---

## 这段话包含的三个决定性 insight

### Insight 1 · 双受众约束

| 受众 | 需求 |
|---|---|
| 观众（游园会路过） | wow、感官冲击 |
| 评委（走动评审） | 看内部技术深度 |

**推论**：必须设计双路径，不能一套方案强行兼顾。

### Insight 2 · "观众不能感受到被懂" 的结构性困境

这是一个极其犀利的观察。

- 观众不是 AI 懂的主体（不是 TA 自己的数据）
- 因此观众**无法真正体验"被懂"**
- 所有依赖"精准个性化"的方案在展台上都失效
- 这堵墙所有赛道三方向都撞

大多数方案**假装没撞到墙**。本方案选择**正视并解决**这堵墙。

### Insight 3 · 突围路径 = 重新定义 + 新数据形式

> "重新定义懂你，同时创新一种数据形式。"

这两件事是**互锁的**：

```
"懂你"的传统定义失效
    │
    ▼
需要重新定义"懂你"
    │
    ▼
新定义需要新的载体
    │
    ▼
创新一种数据形式作为新载体
```

**关键**："新数据形式" 不是装饰，是新"懂"定义的**必要容器**。这就是整个方案的哲学核心。

## 我的回应

### 载体形态锁定

- **A · 沉浸式 Feed 增强** 给观众看（主屏）
- **C · 剧场化双屏** 给评委看（侧屏展示 agent 后台）

### 问题升级

用户说的"重新定义懂你 + 新数据形式"让 Q3 的问题从"UI 选型"升级到"**概念定义**"。下一个问题要问：**"懂你"重新定义成什么？新数据形式的方向是什么？**

## 推演决策

| 项目 | 决策 |
|---|---|
| 载体形态 | A + C 组合 |
| 观众路径 | feed 沉浸（主屏） |
| 评委路径 | agent 后台透明（侧屏） |
| 双受众分路 | 必须 |
| 突围 insight | 正视"观众不能被懂"，用新数据形式解决 |
