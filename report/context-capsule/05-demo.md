# 05 · 展台主 demo 叙事 + Bonus 切换

## 场景设定

- **当前日期**：2026-04-17（春末）
- **距五一假期**：14 天
- **观众画像**：大学生群体
- **展台环境**：游园会、围观 + 近距离互动并行

## 双受众设计（γ 双模切换）

| 模式 | 面向 | 触发 | 什么在跑 |
|---|---|---|---|
| **观众模式**（默认） | 路过者 / 近距离观众 | 持续 | 预计算矩阵（6 目的地 × 3 persona = 18 胶囊）+ 预合成 TTS |
| **评委模式**（按钮切换） | 评委 | 评委来了按键切换 | 1 条真 RAG 链 + 真 LLM 生成胶囊 + Agent Trace 层展开 |

两种模式共享相同的 UI，只切换底层数据路径。
详见 [`06-feasibility.md`](06-feasibility.md)。

## 主 demo · 五一春游预言（90 秒）

### 叙事节拍

| 时间 | 画面 / 动作 | 意图 |
|---|---|---|
| **0-8s** 情境识别 | 大屏低声播报：*"现在是 4 月 17 日下午 3 点 · 已识别大学生群体 · 春季出游情境正在形成"* | 把**情境识别**这个动作外化出来，让观众看到"系统在'此刻'工作" |
| **8-20s** 胶囊诞生 | 观众到达触发 → 胶囊 materialize：标题浮现、TTS 语音主持：*"这是我为你准备的——五一 + 轻徒步 + 寝室三人局 · 3 天 1200 预算能打"*，动态路线图浮现，结构化字段渐进展示 | **胶囊诞生的戏剧性**（核心 wow #1） |
| **20-40s** 第一次变形 | 三个决策按钮出现："出发 / 换目的地 / 换人群"；观众点"换目的地" → 胶囊**实时变形**为"安吉骑行"（同情境不同答案） | **变形的 wow**（核心 wow #2） |
| **40-60s** 第二次变形 | 观众点"换人群" → 从"寝室三人"切换为"情侣二人" → 胶囊路线、预算、证据 chips 全部重排 | **多维变形**（核心 wow #3） |
| **60-80s** 技术揭幕 | 评委侧屏揭开 Agent Trace：*"刚才系统抓了 12 个视频 → 提了 34 个要点 → 匹配了 5 个目的地 → 生成了 3 版胶囊"* | **新数据形式的技术可信度** |
| **80-90s** 收尾 | 定格。观众可重启 / 切 bonus 垂类 | — |

### 三个核心 wow 瞬间

1. **8-12s 胶囊 materialize**：视觉 + 听觉同时启动，标题从虚到实，TTS 声音有温度，路线图浮现。这是"新数据形式"的感官冲击。
2. **25-30s 换目的地变形**：观众的输入立刻改变胶囊，所有字段同步重排。这是"可变形性"的展示。
3. **75-80s Agent Trace 揭幕**：评委看到黑盒被打开——12 个视频、34 个要点、3 版胶囊。这是"可审计性"的展示。

## Bonus 切换 · 晚饭预言台（30 秒）

### 触发方式

- 按钮明显：大屏有"切换垂类"按钮
- 关键词触发：评委说"其他场景呢？"手动切换
- 或观众停留超过 2 分钟自动循环到 bonus

### 叙事节拍

| 时间 | 画面 / 动作 |
|---|---|
| 0-5s | 倒计时显现：*"距晚饭 2h 17min · 正在为大学生准备今晚的饭局"* |
| 5-15s | 预言时刻 materialize → "微雨 + 周末 + 3-4 人饭局 · ¥30-60/人" 情境胶囊出现 |
| 15-25s | 3 家店视觉 hero + 菜品视频剪辑 + TTS："今晚微雨，帮你挑了 3 家能躲雨 + 能聊事 + 便宜的" |
| 25-30s | 观众选 "预算 ¥30" → 胶囊收敛到 1 家 → 出导航 + 点单 + 谁一起去 |

### Bonus 的作用

**反驳"这只是单样本硬编码"的质疑**：
- 同一个胶囊引擎
- 同一套 Schema
- 不同垂类数据
- 证明方案是**引擎级创新**，不是单场景 demo

只要 bonus 能跑通，就从"一个 demo"升级为"一个引擎"。

## 展台物理形态（留给下一阶段细化）

本文档不 freeze 屏数 / 布局 / 触发机制。以下为候选讨论点：

- **单大屏 + 侧屏**：主屏跑观众模式、侧屏展评委模式时展开 Agent Trace
- **大屏 + iPad**：iPad 给观众触屏操作（换目的地 / 换人群），大屏同步
- **双大屏双工**：一屏跑 feed、一屏跑 HUD
- **触发机制**：人体传感器 / 手动按键 / 时间循环

以上在实施阶段再决定。

## 备用脚本（工程风险兜底）

如果评委模式链路翻车，跑纯观众模式 90s。
如果变形切换卡顿，降级到预切换（不是实时变形，是淡入淡出）。
如果 TTS 不可用，用字幕 + 背景音乐替代。
如果 Bonus 超时，只跑主 demo 即可。

## 叙事原则

- **时间感**：反复强调"现在是 4 月 17 日 · 距五一 14 天"，让观众感到"此刻"被认真对待
- **戏剧弧**：识别 → 生成 → 变形 → 审计，有起承转合
- **节奏**：每 8-12 秒有一个新元素进入
- **避免说教**：不解释"这是什么数据结构"，让胶囊**自己演**给观众看
- **评委话术埋点**：TTS 主持词里埋关键词（"为你准备""刚好""情境"），评委听一遍就 get 到概念
