# 字节活动候选方向（基于 allin / Eoove-demo / nightowl / taidy）

调研约束默认统一按这套口径：

- 纯软件开发，不依赖硬件
- 40 小时内能做出可演示 MVP
- 面向大学生展览，优先考虑“上手快、围观效果强、结果个性化明显”
- 尽量复用现有仓库能力：
  - `allin`：学生画像、岗位数据、GraphRAG、路径规划、雷达图/报告
  - `Eoove-demo`：数字个体、问卷、记忆、连接器、顾问、知识图谱
  - `nightowl`：轻量 ETL + pgvector + RAG，适合快速原型
  - `taidy`：NL2SQL、RAG、归因、图表、对话式问数
- 数据获取优先级：`官方 API > 官方导出/用户上传 > 公开数据集 > 小规模人工采样`
- 默认不要假设能调用未公开的抖音接口；如果平台能力未知，先按“样本内容 + 手工 ETL + 本地知识库”设计

---

## 1. 精选视频 -> 未来的你学习搭子

- 适合赛道：赛道二｜抖音精选-内容重构
- 方向：把 AI / 科技 / 职场 / 课程类视频转成“给当前这个大学生”的学习摘要、知识地图、3 天行动计划、1 题小测。
- 可复用项目：`Eoove-demo` 的画像与顾问，`nightowl` 的 ETL/RAG，`taidy` 的引用和图表，`allin` 的学生画像展示。

继续调查可行性的 prompt：

```text
请围绕“精选视频 -> 未来的你学习搭子”做参赛可行性调研，背景是字节跳动举办的大学生活动，要求纯软件、40小时内做完、适合展览。请输出：
1. 这个方向与赛道二的契合点
2. 最小可行 MVP 功能，只保留 1 个垂类（如 AI 学习、实习求职、考研）
3. 数据获取方案，按“官方 API / 官方导出或开放能力 / 公开网页可采集字段 / 人工采样”四级列出；明确是否能合法稳定拿到视频标题、简介、字幕、封面、标签
4. 如果拿不到抖音精选官方内容 API，如何用 30~100 条公开视频样本或人工整理字幕完成 ETL + RAG
5. 现有本地项目中哪些模块可直接复用，分别对应画像、知识库、问答、引用、前端展示
6. 40 小时开发拆解
7. 展台 demo 流程
8. 最大风险与降级方案
```

## 2. 实习求职视频 -> 你的岗位决策卡

- 适合赛道：赛道二 / 赛道三
- 方向：用户输入专业、年级、城市、期望薪资后，把求职类视频和岗位信息重组为“一刷即懂”的岗位卡：适合度、关键词、避坑点、下一步投递建议。
- 可复用项目：`allin` 的岗位库、画像和匹配，`taidy` 的问数/图表，`Eoove-demo` 的 persona 和 advisor。

继续调查可行性的 prompt：

```text
请调研“实习求职视频 -> 你的岗位决策卡”是否适合字节大学生活动参赛，要求纯软件、40小时内能做完。请重点分析：
1. 用 allin 的岗位数据 + 视频内容重构是否能形成清晰故事线
2. 数据侧需要哪些字段：岗位标题、城市、薪资、技能、视频摘要、用户画像字段
3. 这些字段分别可以从哪里获得：现有 allin 数据库、公开视频页面、手工标注、校园招聘公开信息、官方 API
4. 是否有必要接入实时招聘 API；如果没有稳定 API，如何用静态岗位库做出可信 demo
5. RAG 和用户画像在这里分别扮演什么角色，怎么避免只是普通聊天框
6. 40 小时 MVP 的技术拆解与最省时间的架构
7. 展台上 30 秒内让观众看懂的交互脚本
8. 风险：数据时效性、版权、平台接口、推荐真实性
```

## 3. 选课 / 竞赛 / 考研内容 -> 个性化成长路线图

- 适合赛道：赛道二
- 方向：把选课、竞赛、考研、技能成长相关内容，按“大一 / 大二 / 大三 / 跨专业 / 保研 / 找工”画像重组为路线图，不是推荐视频，而是直接给行动路径。
- 可复用项目：`allin` 的路径规划和图谱，`Eoove-demo` 的人格与长期记忆，`nightowl` 的轻量知识库。

继续调查可行性的 prompt：

```text
请调研“选课/竞赛/考研内容 -> 个性化成长路线图”这个方向的参赛可行性。输出时重点回答：
1. 它更适合赛道二还是赛道三，为什么
2. 若复用 allin 的 GraphRAG 和路径规划思想，如何把“职业路径”改造为“大学生成长路径”
3. 数据从哪里来最稳：学校公开培养方案、课程介绍页、竞赛官网、公开视频字幕、手工整理资料、用户输入
4. 哪些数据可以直接抓取或下载，哪些需要人工录入
5. 是否存在可用的官方 API；如果没有，MVP 应该如何规避 API 依赖
6. 40 小时内建议保留的功能上限
7. 展示层是否适合用桑基图、路线图、雷达图，哪个最容易打动展台观众
8. 风险和降级策略
```

## 4. 你刷过什么，就长成什么：内容消费人格镜像

- 适合赛道：赛道二 / 赛道三
- 方向：把用户最近看过的一组内容，转成“兴趣偏好 + 行动倾向 + 学习风格”的数字镜像，再反向生成更懂你的内容解释和建议。
- 可复用项目：`Eoove-demo` 的 PersonVec/记忆块/报告，`nightowl` 的 ETL，`taidy` 的归因面板。

继续调查可行性的 prompt：

```text
请评估“内容消费人格镜像”作为字节大学生活动作品的可行性，要求和数字个体、ETL、RAG、用户画像强相关。请输出：
1. 这个方向如何避免变成泛人格测试，而是与内容消费场景强绑定
2. 数据来源方案：是否可以通过用户上传观看记录截图、收藏夹导出、手填近10条内容、公开视频样本来构建画像
3. Eoove-demo 的问卷、memo、diary、reading、connector 中哪些能力可以直接复用
4. 用户画像如何设计成“看得懂、愿意玩、不会觉得玄”
5. 是否需要真实抖音行为数据；如果没有平台接口，如何用替代输入完成 demo
6. 40 小时 MVP 功能和页面清单
7. 展台效果最强的展示方式
8. 风险：隐私、数据噪声、人格标签过强
```

## 5. 懂你的一刷：今晚吃什么 / 周末去哪卡片流

- 适合赛道：赛道三｜AI体验
- 方向：做一个“刷到就能直接决定”的信息卡单元。用户先给预算、人数、口味、距离、情绪，接着连续刷到已经帮他排好的选择卡。
- 可复用项目：`Eoove-demo` 的顾问、画像、决策记录，`taidy` 的卡片式结果与归因，`nightowl` 的轻量知识库。

继续调查可行性的 prompt：

```text
请围绕“懂你的一刷：今晚吃什么 / 周末去哪卡片流”做参赛可行性调研，要求偏赛道三、大学生展览友好、40小时可完成。请重点调查：
1. 这个方向为什么适合“刷到懂你的瞬间”
2. 数据来源最稳的方案：大众点评/小红书等第三方 API 是否现实；如果不现实，是否可以用校园周边公开商家信息 + 人工整理菜单/地点/价格
3. 用户画像最小集合需要哪些字段，怎样 15 秒内采集完
4. 结果卡片里最应该展示哪些内容，才能在展台现场一眼懂
5. 是否需要地图 API、路线 API、天气 API，哪些是必须，哪些可砍
6. 如何用现有本地项目快速搭出“画像 + 决策 + RAG + 卡片流”
7. 40 小时 MVP 方案
8. 法律和平台风险
```

- 可复用项目：`allin` 的匹配思路，`Eoove-demo` 的 advisor 和 schedule，`taidy` 的多意图规划。

继续调查可行性的 prompt：

```text
请调研“校园活动/社团/讲座/宣讲会智能信息流”是否适合本次字节活动。请输出：
1. 赛道匹配分析
2. 可用数据源：学校官网、学院通知、公众号文章、报名表单、海报 OCR、日历 ICS、公开 RSS 等
```

## 7. 平行人格互动剧场

- 适合赛道：赛道一｜互动空间
- 方向：用户先快速生成一个数字分身，然后进入 3 个大学生活场景分支，例如选课、社交、实习、旅行。不同画像走出不同剧情。
- 可复用项目：`Eoove-demo` 的数字个体和 memory，`allin` 的画像维度，`nightowl` 的轻量记忆检索。

继续调查可行性的 prompt：

```text
请评估“平行人格互动剧场”作为赛道一作品的可行性，要求和数字个体、用户画像强关联，40小时内可做。请重点回答：
1. 赛道一强调可直接玩到，这个方向的最小玩法是什么
2. 是否必须接入抖音互动空间官方能力，还是可以先做网页/小程序式原型再迁移
3. 现有 Eoove-demo 的数字个体、问卷、顾问能力如何最少改造就能进入剧情互动
4. 剧情数据如何准备：手工写 20~30 个节点、从公开视频/帖子里抽校园案例、还是从问卷模板生成
5. RAG 在这里的价值是什么，如何避免剧情只是模板拼接
6. 展台上最抓人的 1 分钟体验路径
7. 40 小时内的美术/UI/交互边界
8. 最大风险与最稳降级版本
```

- 可复用项目：`taidy` 的问答+归因，`Eoove-demo` 的用户画像，`nightowl` 的轻量 RAG。

继续调查可行性的 prompt：

```text
请评估“暂停、圈选、追问：视频知识点即时学习卡”作为赛道四作品的可行性，要求纯软件、40小时内能做。请重点调查：
1. 这个方向最小闭环是什么：截图上传 + 框选 + OCR + 追问，还是只做静态图像上传
2. 哪些能力需要官方 API，哪些可以用通用 OCR、视觉模型、语音转文本 API 完成

4. 数据层是否需要单独知识库，还是只靠通用模型 + 小型课程资料库即可
```

## 我当前更看好的 5 个优先方向

1. 精选视频 -> 未来的你学习搭子
2. 实习求职视频 -> 你的岗位决策卡
3. 懂你的一刷：今晚吃什么 / 周末去哪卡片流
4. 平行人格互动剧场
5. 暂停、圈选、追问：视频知识点即时学习卡

原因很简单：这 5 个方向和你现有仓库能力的重合度最高，纯软件完成度更稳，展台上也最容易让人“10 秒内看懂你在做什么”。
